# 架构说明

## 1. 架构决策（ADR）

### ADR-001 模块化单体，不拆微服务
- 状态：已落地
- 决策：Spring Boot 单应用，按业务域分包：`auth / platform / store / product / purchase / inventory / sales / member / supplier / franchise / settlement / mall / report / system / mp / cms / staff / app`。
- 理由：单租户 200 门店量级、团队规模有限、事务与排障成本优先。跨模块通过 Service 接口调用，禁止跨包直接访问 Mapper。
- 后续拆分阈值：单表 > 1000 万行或单库 > 200GB 时按 `tenant_id` 评估分片；租户 > 50 或单租户 > 500 万行时评估独立 schema。当前明确不做微服务/K8s/分库分表。

### ADR-002 一个后端 + 多前端壳
- 状态：已落地
- 决策：平台端、租户后台、官网、H5、4 个小程序、Flutter App 共用 `/api/v1`、RBAC、UnionID 会员、租户上下文、对象存储与消息通道。
- 差异只在界面、角色可见范围与端专属接口（`/staff/*`、`/supplier/*`、`/franchisee/*`、`/app/*`）。
- 后果：新增端只增加前端壳 + 角色 + 菜单；接口变更保持 `/api/v1` 兼容。

### ADR-003 共享库 + tenant_id，预留升级路径
- 状态：已落地
- 决策：共享库行级隔离；MyBatis-Plus `TenantLineInnerInterceptor` 强制注入；平台表白名单（`platform_*`）；`TenantContext` ThreadLocal 贯穿请求。
- 升级阈值写入 ADR-001。

### ADR-004 平台端与租户后台物理分离
- 状态：已落地
- 决策：路由前缀 `/api/v1/platform/*` 与 `/api/v1/tenant/*`；平台账号存 `platform_user`，租户账号存 `sys_user`；两套菜单、角色、登录入口；`AuthFilter` 双向拦截越端访问，返回 403。
- 平台端只提供汇总与计费，不提供租户订单/会员/库存明细接口。

### ADR-005 公众号一 appId 一租户
- 状态：已落地（真实微信侧受凭证阻塞）
- 决策：`mp_account` 按租户唯一；AppSecret/Token/EncodingAESKey AES-GCM 加密、掩码展示、留空不改；接号前执行占用检查并落库；回调地址 `/admin-api/mp/open/{appId}`。
- 回调支持明文模式验签、关注/取关、文本消息、关键词/关注自动回复；AES 安全模式明确返回不支持提示。

## 2. 模块边界

| 模块 | 职责 | 边界 |
|---|---|---|
| auth | 登录、JWT、租户上下文、菜单下发 | 不承载业务规则 |
| platform | 租户、套餐、配额、账单、公告、平台审计、平台账号 | 不读取租户业务明细 |
| store | 门店档案、状态、证照、稽核 | 不负责库存 |
| product | 分类、品牌、SPU/SKU、条码、多价格、Excel | 不做库存扣减 |
| purchase | 采购、供货、收货、差异、补货建议 | 收货确认后才写库存 |
| inventory | 库存、批次、流水、调拨、盘点、报损、预警 | 不负责销售定价 |
| sales | 线上/收银订单、支付、退款、交接班、日结 | 不内置 POS 硬件驱动 |
| member | 会员、等级、积分、储值、券、活动 | 触达调用消息能力 |
| supplier | 供应商档案、资质、供货商品、供应商端 | 结算由 settlement 负责 |
| franchise | 加盟商、门店绑定、分账、加盟商端 | 不做资金二清 |
| settlement | 供应商/加盟商对账单、开票 | 仅生成账单与对账 |
| mall | 配送规则、公开商城接口 | 与门店库存联动 |
| mp | 公众号 11 子页、微信回调 | 菜单编辑归菜单可视化 |
| system | 参数、i18n、菜单、消息、SSO、存储、RBAC、审计 | 不承载业务 |
| report | 销售/毛利/库存/会员/供应商/加盟报表 | 只读聚合 |

## 3. 核心数据流

### 线上下单 → 支付 → 履约
1. `POST /api/v1/app/orders`：校验门店营业/配送范围/起送价/烟草禁售，计算会员价、活动价、券、积分，创建订单并预占 `stock.locked_qty`。
2. `POST /api/v1/app/orders/{id}/pay`：储值或模拟微信支付，提交预占库存、扣减批次（效期优先），订单转 `PENDING_ACCEPT`，写入积分为消费积分。
3. 门店 `accept → pick-complete → complete`；自提转 `WAIT_PICKUP`，外送转 `DELIVERING`。
4. 退款：退款单落库、库存回库、储值退回、优惠券/积分回滚。
5. 超时：定时任务每 60s 取消 15 分钟未支付订单与超过接单截止时间的已支付订单，自动退款回库。

### 订货 → 收货 → 库存
1. 补货建议按近 30 天销量、当前库存、在途、安全库存、保质期、后台系数计算。
2. 采购单审核后可转供货单；供货单 `PENDING → ACCEPTED → SHIPPED`。
3. 门店收货逐项录入实际数量、生产/到期日、批次、冷链温度（冷藏/冷冻必填），差异生成差异单，确认后才入库并写批次/流水。

### 结算
- 供应商：按收货明细（实收数量 × 供货价）生成对账单 → 确认 → 付款 → 开票记录。
- 加盟商：按周期销售额 × 分账比例（或固定额）生成对账单与分账记录；平台不做资金二清。

## 4. 容量与故障

| 项 | 当前设计 | 阈值/降级 |
|---|---|---|
| 下单/查询 | 单应用 + MySQL + Redis | 查询 P95 目标 <500ms，收银 P95 <300ms（未做压测证据） |
| 缓存 | `tenant:{id}:*`，权限/租户状态/序号/令牌 | 租户停用清缓存 |
| 消息 | Spring 事件/同步；RabbitMQ 已编排未生产验证 | MQ 故障不影响主交易（当前未强依赖） |
| 单机部署 | Compose 单点 | 每日备份 + 恢复演练 + 进程守护；故障时读缓存降级 |
| 定时任务 | 按租户遍历，单租户失败不影响其他租户 | 失败写日志，下一周期重试 |

## 5. 已知边界（不承诺过度）
- 不内置 POS 硬件、电子秤、钱箱、小票机驱动；小票使用浏览器打印。
- 烟草商品可建档但线上强制不可售。
- 称重商品按重量计价，读数需人工录入。
- 支付/微信/短信/OSS/COS 的第三方真实联调受客户资质与凭证阻塞，见 `docs/acceptance.md`。
